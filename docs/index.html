預設工作流

這版不是照 upstream 原樣搬過來，而是直接改成你現在實際會用的順序。

Claude 優先
主畫面與 demo 都以 Claude 作為第一優先顯示，適合你平常做主要實作與收尾。
Codex / Copilot 常駐
預設音效與 demo 流程都把 Codex、Copilot 放到核心工作流，不再只是附屬 provider。
Gemini 次要
預設不幫 Gemini 配提示音，保留給實驗或備用，不去搶主監控注意力。
完全分家
設定檔、音效資料夾、port 檔、hook sidecar 都改成 lobsterpulse，不跟舊專案共用。

可重建

原始碼建置

如果你之後要打新的 release 或 bundle，直接從 repo 內重建，不需要回頭依賴上游產物。

⚠️ release 必須走 cargo tauri build --no-bundle，不可純 cargo build --release（Tauri v2 release webview 會 fallback 到 devUrl 白屏）。前置 cargo install tauri-cli --locked。

cd src-tauri
cargo tauri build --no-bundle    # 快速驗證：exe + embed frontend，無 installer
cargo tauri build                 # 完整 installer：.msi / .deb / .AppImage（需 tauri-cli）

三方對齊 README.md + CLAUDE.md「Build SOP（重要）」段 + build.sh。

建置與啟動

這三個入口對應你最常用的維護節點：跑程式、重生資產、打 bundle。

直接跑 release 產物

src-tauri\target\release\lobster-pulse.exe
src-tauri\target\release\lobster-pulse-hook.exe

兩個檔案要放在同一層，主程式會用相鄰路徑找到 sidecar。

重生品牌資產

.\scripts\generate_brand_assets.ps1

這會一起更新 docs logo、Windows icon、icon.icns、iOS 與 Android icon。

從原始碼重建

cd src-tauri
cargo build --release

如果之後要打完整 bundle，再另外補裝 cargo-tauri 後跑 cargo tauri build。

Repo 維護方式

這份 clone 不再只有單純改檔，而是整理成你自己的產品線：保留上游、分出品牌主線、日後可再掛你的 origin。

保留上游來源

origin 會改名成 upstream，之後你要拉 AgentPulse 新版本時，不會跟你自己的 repo 混在一起。

品牌主線

主開發分支改成 lobsterpulse/main。你的品牌版變更都沿著這條線走，不再直接堆在上游 main 上。

日常功能分支

後續新功能建議從 feature/* 開出去，做完再回 merge 到 lobsterpulse/main，保留可追蹤的維護節奏。

建議日常流程

git checkout lobsterpulse/main
git checkout -b feature/your-change
git add .
git commit -m "feat: ..."
git checkout lobsterpulse/main
git merge --ff-only feature/your-change

如果你之後建立自己的 GitHub repo，再把它加回 origin，保留 upstream 指向原始 AgentPulse 即可。
